# Plan: detection settings per camera in the wand tab (13 Oct 2026)

**Your question:** "for the gui for refract+cylinder, i find that i still cannot set object parameters for each
camera? for example, the wand opening, wand mask, radius range? i think that is important if my cameras have
different resolutions?"

## 1. What the GUI does now

**The settings are shared.** The wand tab's Point Detection panel has one Radius Range, one Sensitivity and (in the
ellipse mode) one Rod opening and one Rod mask. They serve every camera. The detection tab is the same for every
model (Pinhole, Pinhole+Refraction, Pinhole+Cylinder).

**The one per-camera handle is the camera table's Pixel (µm) column.** With it set for every camera, the shared
lengths are taken in the first camera's pixels, and a camera with pixels p gets them times p₁ / p
(`scale_detect_settings` in `wand_calibrator.py`). That is right only when the cameras differ in pixel size alone.
- It is wrong when the magnification differs: another lens, focal length, distance, or a camera binned or cropped
  differently.
- In general a ball's image radius goes as f / distance, which is not known before the calibration.

**Your point stands.** Cameras that see the balls at different sizes need their own values.

**The code is ready for it.** The calibrator already builds each camera's detection task on its own (one
`(min radius, max radius, sensitivity, opening, mask)` per camera and image). The later steps, which pair the balls
and filter the frames, never use these values. So only what each task receives has to change.

## 2. What I propose

A checkbox, **"Different settings for each camera"** (off by default), with a small table of every camera's values.
The table sits just above Test Detect, where you tune:

```
Detection Mode: ( ) fast  ( ) reliable  (•) ellipse
Rod opening:  [ 25 px ]                 <- greyed while the box is ticked
Rod mask:     [ 18.0 px ]               <- greyed
[x] Different settings for each camera
  Cam | R min | R max | Sens. | Opening | Mask
   0  |   40  |  120  | 0.85  |    95   | 50.0
   1  |   30  |   90  | 0.85  |    70   | 38.0
   2  |   25  |   80  | 0.80  |    60   | 32.0
[ Test Detect (Current Frame) ]
[ Process All Frames / Resume ]
```

- **Per camera:** the Radius Range (min and max), the Rod opening and the Rod mask, as you asked. I would add the
  Sensitivity: lighting can differ between cameras, and it costs one column.
- **Shared:** the Wand Type and the Detection Mode stay one for all cameras.
- **Box off:** everything is exactly as now (the shared values, scaled by the Pixel column if it is set).
- **Ticking the box** fills each camera's row from the shared values, times its pixel-size factor when the Pixel
  column is set. So nothing changes until you edit a row.
  - **While ticked:** each row is in that camera's own pixels. The pixel-size factor is not applied again; the
    Pixel column then only prints f in mm on the results page. The shared Radius Range, Sensitivity, Rod opening and
    Rod mask are greyed.
  - **Unticking:** the shared values are used again. The rows are kept for the next time the box is ticked.
- **The table follows Num Cameras:** the cameras that remain keep their rows, and a new camera starts from the
  shared values. Opening and Mask show only in the ellipse mode.
- **Every detection uses it:** Test Detect, Process All Frames / Resume, and the custom axis points' Detect. The
  console line of a detection lists each camera's values.
- **Each row's maximum radius** is limited to a quarter of that camera's shorter image side, as the shared slider is
  now.

**Why a table** rather than a camera selector over the existing sliders: every camera's values are visible at
once, and there is no hidden "which camera am I editing" state. It fits the panel's width, about 300 px, as the
camera table does.

## 3. The code changes (only these files)

1. **`modules/camera_calibration/wand_calibration/wand_calibrator.py`:**
   - **A helper, `camera_detect_settings(...)`,** gives one camera's (min radius, max radius, sensitivity,
     ellipse options): its own row when there is one, else the shared values through `scale_detect_settings`,
     unchanged.
   - **The two places that build tasks** (`detect_wand_points_generator` and `detect_single_frame`) call it.
   - **A new optional argument, `cam_settings`,** is accepted by those two and by the two detection workers. When it
     is None, the tasks are exactly today's.
2. **`modules/camera_calibration/view.py`** (the wand tab in use, `create_wand_tab_v2`, and its helpers):
   - the checkbox and the table;
   - `_wand_cam_settings()`, which returns None when the box is off;
   - the table's rows, kept when Num Cameras changes;
   - the three detection calls pass `cam_settings`;
   - the shared controls greyed while the box is ticked;
   - the Pixel column's tooltip.
3. **The user guide** (`WAND_CALIBRATION_USER_GUIDE.md`, the HTML rebuilt):
   - the new checkbox and table in §3's settings table;
   - the Pixel (µm) row says its factor applies only to shared settings.
4. **`tests/cylinder_wand/README.md` and `tests/plate_wand/README.md`:** a progress-log entry.
5. **This folder** (plan, check, results, report), tracked through a `.gitignore` negation without its `data/`.

**Not touched:** the detectors themselves, the pairing and filtering, the calibrations, and the other copies of the
wand tab in `view.py` (unused).

## 4. The check (light, as for the other GUI changes)

cameras), in the GUI's own window off the screen:
- **K1, nothing changes with the box off.**
  - With the box off, Test Detect gives the same points as the shared settings do directly, with and without the
    Pixel column set.
  - With the box ticked and its rows untouched (filled from the shared values), it gives the same points again.
- **K2, each camera gets its own values.**
  - The shared Radius Range is set to fit both cameras, and cam 1's row to its balls.
  - cam 2's maximum radius is set below its balls: cam 2 must find none of them, and cam 1 must still find both.
  - Then, with Process All Frames on the six frames, the written file must have cam 1's balls and not cam 2's.
- **K3, the panel.**
  - The table follows Num Cameras 2 → 3 → 2 (rows kept, the new one from the shared values).
  - Opening and Mask show only in the ellipse mode.
  - The shared controls are greyed while the box is ticked.
  - The panel still fits its 358 px width without a horizontal scroll bar.
  - A screenshot of the panel, which I look at.
