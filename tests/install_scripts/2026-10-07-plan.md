## 1. What is wrong

The diagnoses below are read-only: dry-run solves (`conda create --dry-run`, no environment made), `conda search`, and
reading the scripts. Their outputs are beside this plan.

**The installers cannot install the package list (D1).**
- `requirements.txt` lists `pycine`, which is **not on conda-forge**, for any platform (win-64, linux-64,
  osx-arm64, osx-64).
- So `mamba install -c conda-forge --file requirements.txt` stops with
  `PackagesNotFoundError: pycine[version='>=0.3.2']` (`d1_current_requirements_dryrun_out.txt`).
- All three installers and `update_openlpt.bat` run that command: a fresh install fails at its step 3 on every
  platform.
- pycine is on PyPI, and `pyproject.toml` already lists it, so `pip install .` would install it.

**The Windows installer needs mamba.**
- `install_windows.bat`, `install_mac.command` and `update_openlpt.bat` call `mamba` unconditionally.
- Anaconda and Miniconda have only `conda`. This PC has Anaconda without mamba, so the installer would fail here even
  without the pycine problem.
- `install_linux.sh` already falls back to conda.

**On Windows the solve picks MKL for BLAS (D2, D3).**
- With the current list, conda-forge's solve on win-64 chooses MKL: `libblas …_mkl` in `d2_dryrun_out.txt`.
- That is the set-up that crashed numpy in the refract env. `np.linalg.solve` killed the interpreter (0xc06d007f, a
  delay-loaded DLL not found) with `python.exe` started by its path, without `conda activate`. That is how the GUI's
  desktop shortcut starts it. Whether activation would avoid the crash was not tested. It would take out every
  calibration.
- With `libblas=*=*openblas` added, the solve picks OpenBLAS, the same build as refract
  (`libblas-3.11.0-11_h0adab6e_openblas`, `d3_dryrun_out.txt`).

**The Report tab's QtWebEngine is in no list.**
- The camera calibration's Report tab needs `qt6-webengine` from conda-forge. I added it to refract by hand on
  6 Oct.
- Without it the tab shows a short summary and a button that opens the page in the browser.
- conda-forge has it for win-64, linux-64 and osx-arm64, **not for osx-64** (Intel Macs).

**Python 3.10.**
- The scripts and the README create Python 3.10 environments.
- Everything since September was developed and tested on refract's Python 3.11.
- numpy ≥ 2.3 and scipy ≥ 1.16 need 3.11, so a 3.10 environment gets numpy 2.2 and scipy 1.15, never tested with
  this code. The code itself parses with the 3.10 grammar (63 files).

**Smaller things.**
- **Visual Studio path:** `update_openlpt.bat` hard-codes VS 2022 *Community*'s `vcvarsall.bat`. It fails with the
  Build Tools (which the installer installs) or the Professional edition; the installer itself finds VS with
  `vswhere`.
- **Mixed channels:** the scripts create the environment from the user's default channels, then install from
  conda-forge. On a machine where Anaconda's `defaults` channel comes first, that mixes channels: slower solves,
  possible conflicts, and in recent Anaconda versions a Terms-of-Service prompt that stops a scripted install. Not
  testable here: this PC has conda-forge first and the terms accepted (`d4_default_channels_dryrun_out.txt`).
- **Wrong command in pyOpenLPT's `CLAUDE.md`:** it says `pip install -r requirements.txt`. That cannot work:
  `requirements.txt` uses conda-forge names (`opencv`, `cxx-compiler`, `llvm-openmp`), which do not exist on PyPI.
- **Unused or unlisted packages:**
  - **numba:** in both lists, but imported nowhere;
  - **pandas:** only test and demo scripts import it;
  - **cma:** only `run_full_global_search.py`, a standalone script, imports it, and it is in no list.

**What must not break: the CI.** Three GitHub workflows (`linux_build`, `macos_build`, `pr_tracking_regression`) read
`requirements.txt` with pip. They first change `opencv>=` to `opencv-python>=` and drop the `cxx-compiler`,
`llvm-openmp` and `cmake` lines. A conda-only line, such as `qt6-webengine` or the BLAS pin, would break that pip
install. Those lines therefore go in the scripts, not in `requirements.txt`.

## 2. Changes proposed

| file | change |
|---|---|
| `requirements.txt` | ~~Remove `pycine`~~ (your answer: keep it). Mark its line `# pip-only: not on conda-forge`. Add a comment header: conda-forge names, read by the installers and, after a pip rewrite, by the CI; the platform extras come from the scripts. |
| `install_windows.bat` | (a) Use mamba if present, else conda. (b) One solve, conda-forge only (`--override-channels`), Python 3.11: `requirements.txt` plus `qt6-webengine`, `pywin32` and `libblas=*=*openblas`; an environment that already exists is updated with the same specs instead of half-failing. | `install_linux.sh` | Python 3.11, conda-forge only, plus `qt6-webengine`; the optional environment name. |
| `install_mac.command` | mamba or conda; Python 3.11; conda-forge only; `qt6-webengine` on Apple silicon only (on Intel Macs the Report tab opens the page in the browser); the optional environment name. |
| `update_openlpt.bat` | mamba or conda; `vcvarsall.bat` found with `vswhere` (any VS 2022 edition or the Build Tools); the installer's specs (`qt6-webengine`, the OpenBLAS pin), conda-forge only; the optional environment name. |
| `README.md` | Method 3 (manual): Python 3.11 and the conda-forge command with `requirements.txt`. One line on the Report tab's QtWebEngine, and one on the OpenBLAS pin on Windows. |
| `CLAUDE.md` (pyOpenLPT) | `pip install -r requirements.txt` becomes the conda command. |

**Options, your choice:**
- **O1:** drop `numba` from `requirements.txt` and `pyproject.toml`. It is imported nowhere and is a large package
  (numba plus llvmlite). Keep `pandas`, which the test and demo scripts use.
- **O2:** the installers delete the whole `build\` folder before building. In this working copy that folder holds
  `build\Release\OpenLPT.exe`. Limit the cleanup to setuptools' `build\temp.*` and `build\lib.*`; `setup.py`
  already cleans a CMake cache made with another generator.
- **O3:** list `cma` as an optional package for `run_full_global_search.py`. I would not: nothing in the GUI uses it.

**Not changed:**
- `setup.py`, `build_local.py`, the CMake files, `pyproject.toml` (unless O1), the CI workflows;
- your `refract` and `OpenLPTGUI` environments.
