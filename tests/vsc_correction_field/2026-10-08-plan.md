## 1. Facts first

**What the self-calibration found** (`tests/cylinder_selfcal/2026-10-08-report.md`):
- A smooth correction field per camera, fitted from T1's long tracks, helps T1 modestly. With two passes at a 1.0 px
  tolerance, T1 has 329 real long tracks at frame 100, against today's 296 (+11 %), and 39 % ghosts against 50 %.
- At today's 1.5 px the correction changes nothing.
- **It takes two or three passes.** Each pass's tracks under-report the error that is left, because the matching
  tolerance selects the particles.
- On the synthetic sets, one pass recovers 0.69 / 0.80 / 0.89 of the error with 2 / 3 / 4 cameras.
- There, the frames were warped by the field and the library was not changed.

**What the field means.** c(d) is defined at a detection's pixel d: the camera model's image point of a detection at
d is d − c(d). This is selfcal's convention, so its fields can be used as they are.

**The GUI's VSC can't run on cylinder cameras today** (`modules/vsc/vsc_service.py`):
- It reads a PINCYL file as a plain pinhole. `parse_camera_file` keeps K, R, t and the distortion and drops the tube.
- It sends every model other than PINPLATE down the pinhole path. It would project the tracks without the tube, then
  either find too few points, or fit a pinhole camera and point config.json at it.

**The library has no place for such a correction.**
- The camera models are classes behind one interface (`inc/libMath/Camera.h`).
- STB uses only that interface: `src/srcSTB` casts to no concrete camera type. The C++ VSC that does is switched off
  (`STB.cpp`: `skip_vsc = true`).
- The only casts are in two places:
  - the bubble-radius code (`ObjectInfo.cpp`, pinhole and plate only);
  - the parameter getters and setters of the Python camera handle (`py_camera_handle.h`).
- An OpenLPT.exe built before this change would only warn about a new config key ("unknown setting … is ignored").

**Today's library is p4c's source.** HEAD has no change in `inc/`, `src/` or `cmake/` since p4c was built (`git
diff`), so p4c is the baseline for "off is unchanged".

## 2. The library: an optional correction per camera

**In config.json**, an optional key per camera:

```json
"cameras": [ {"file": "cams/cam1.txt", "max_intensity": 255, "correction": "camFile_VSC/vsc_cam1_corr_p2.txt"} ]
```

- **Without it nothing changes.** No wrapper is created, so the code path is today's.
- **With it**, the camera loaded from "file" is wrapped in a `CorrectedCamera`. The path is relative to config.json,
  like "file".
- Text configs (config.txt) stay as they are.

**The correction file** is text, written by the VSC:
- **Layout:** a header; the image size, which must equal the camera's; the grid (origin, step 8 px, number of nodes);
  then du and dv at the nodes.
- **Evaluation:** bilinear between nodes, and the edge value beyond the grid.
- **Accuracy:** the fitted fields vary over ~130 px (their B-spline knots), so an 8 px grid reproduces them to about
  0.001 px.
- **Size:** about 0.3 MB per camera.

**`CorrectedCamera`** (new `inc/libMath/ImageCorrection.h` and `src/srcMath/ImageCorrection.cpp`, added to the build)
wraps any camera:

| method | with the correction |
|---|---|
| `lineOfSight(d)` | the inner model's line of sight of d − c(d) (explicit) |
| `project(X)` | the d with d − c(d) = q, where q is the inner model's projection: the fixed point d ← q + c(d), to 1e-9 px (with \|∇c\| ~ 0.01, 4–5 steps) |
| `projectWithHint`, `projectAll` | the same, on each image; hints stay the inner model's rays |
| `imageStatus` | curved ports: their rule, applied to the corrected images (the rule moves into a helper both use); single-valued models: `project()` and the sensor, as now |
| `lineImagesCurve` | pinhole and plate: true, since a varying shift bends their straight line images; curved ports: unchanged |
| `type`, `multiValued`, `provablySingleImage`, `usesProjectionHint`, `hintFromLineOfSight`, `clipToModel`, image size | the inner model's |
| `saveParameters` | the inner model's file only; the correction stays in its own file |
| `clone` | clones the inner model and shares the read-only field |

**Two other places change:**
- **Bubble-radius code** (`ObjectInfo.cpp`): it reads focal lengths through the wrapper, so a corrected pinhole
  camera keeps its bubble sizing. Tracers and curved ports don't use this code.
- **Bindings:**
  - new `lpt.ImageCorrection`: load, evaluate, to-model, to-image;
  - new `lpt.CorrectedCameraModel`: a `CameraModel` with `inner()` and `correction()`;
  - `lpt.loadCameraModel(file, correction="")`;
  - `lpt.Camera.setCorrection(path)` and `clearCorrection()`: the handle's projection and line-of-sight calls then
    go through the correction, and its parameter calls keep acting on the inner model.

**One edge case, documented but not fixed.** A curved port's `project()` picks its primary image from the
uncorrected positions. That choice can differ from one made on the corrected positions only when one image lies
within |c| (~2 px) of the sensor edge while another image is on the sensor. `imageStatus` then says Ambiguous, which
is the cautious answer.

## 3. The GUI: VSC for cylinder cameras

**Which path a run takes** (`VSCService.run`):
- If any camera in config.json is PINCYL or PINSPH (read through the C++ loader), it takes the new field VSC.
- Otherwise it takes today's path, unchanged.
- The field path refuses to run if the module has no `lpt.ImageCorrection`. Otherwise tracking would ignore the
  correction it writes.

**The field VSC** (new `modules/vsc/field_vsc.py`, plus `correction_io.py` for the file) is selfcal's estimator, at
the settings the campaign chose:
- **Points:**
  - frames spread over the run, enough to reach "Sample Points" (20,000);
  - in each frame, every point of every long track of at least "Min Track Length";
  - no isolation test and no voxel cap (your point about VSC's criteria).
- **Detections:** the run's own detector. With the config's `"detector": "lines"`, that is the line detector with its
  noise per camera; otherwise ObjectFinder2D.
- **Pairing:** one to one, nearest first, within the "Proj. Tolerance" radius. Its default, r + 1, is 3 px for T1,
  as in selfcal.
- **The fit:** projected least squares, using only the part of the residuals that no 3-D move explains. It works with
  2, 3 or 4 cameras. The Jacobians come from central differences (0.01 mm).
  - **Model:** a cubic B-spline with 10 × 6 intervals per camera and component, with a bending penalty and a 1 px
    prior.
  - **Weights:** Cauchy (c = 2).
  - **Noise:** √(s_f² + (βL)²), with s_f ≥ 0.15 px.
  - **λ:** chosen by the held-out loss on alternate frames.
  - **Beyond the data:** filled from the nearest covered point, 48 px out.
- **"Min Valid Points"** is the minimum number of paired points per camera.

**Passes:**
- **Each pass fits what is left.** When a camera already has a correction c1, the new pass fits c2 against the
  corrected model and writes the total, c(d) = c2(d) + c1(d − c2(d)).
- **Files:** each pass writes `camFile_VSC/vsc_cam{k}_corr_p{n}.txt` in the project folder and points config.json at
  it. Earlier passes' files stay, and config.json is backed up once, as today.
- **A guard:** VSC stops, saying "rerun tracking first", when the tracks are older than the current correction.
  Fitting twice on the same tracks chases a selection that only a new run changes.
- **The log** gives, per camera:
  - the field's size;
  - the change this pass made, which tells when to stop (on T1 the second pass changed less than the first);
  - the epipolar offsets before and after (median, robust SD).

**Tolerance:** as D1 decides.

**The tracking view:**
- **VSC group:** one line on what VSC does for cylinder cameras, and the current pass.
- **Finish message:**
  - the files written and the pass;
  - the epipolar spread before and after;
  - the next step: "rerun tracking, then VSC again; two passes recommended".
- **2-D overlay:**
  - green: the projections through the corrected cameras (`lpt.Camera` + `setCorrection`);
  - yellow: the projections before this pass;
  - red: the detections, as now.
- **A "Correction field" plot** per camera: arrows on a coarse grid over the sensor, the magnitude in colour, and the
  covered area outlined.
- **Checks:** these are display changes, so they get your light checks (it renders, looks right, no errors).

**L0. Off is unchanged.**

**L1. The wrapper, method by method.**
- **Cameras:**
  - T1's two PINCYL cameras;
  - the pinhole `tests/cylinder_stb/data/cams_T2_pinhole/cam1.txt`;
  - a PINPLATE camera of the plate case;
  - T1's cam1 relabelled PINSPH.
- **Points:** 2,000 over the view volume, including points with no image, two images or an image at the sensor edge.
- **A zero field:** every method returns the inner camera's result bit for bit.
- **A smooth analytic field (up to 3 px), and T1's fitted field:**
  - the C++ evaluation equals a Python reference to 1e-12 px;
  - `project(X) − c(project(X))` equals the inner projection to 1e-9 px;
  - `lineOfSight(project(X))` passes within 1e-9 mm of X;

  - `projectWithHint` along a track equals `project`;
  - `imageStatus` follows the corrected images, including images that a constant 3 px field pushes over the sensor
    edge;

- **Config:** a relative "correction" path is found. A wrong image size or a missing file is a fatal error naming the

- **Handle:** `lpt.Camera.setCorrection` gives the wrapper's results, and the handle's parameter calls still work.

  - the swirl estimate of ghosts;

  - the epipolar offsets.
- **Pass:** tracks and real-track estimates within ±5 %, and offsets within 0.05 px. The two can't be identical,

## 7. Decisions

**D1. The 2-D tolerance after a cylinder VSC.**
- **Today's rule:** VSC sets `ipr.tol_2d_px` to the mean + 3 SD of the re-triangulated reprojection errors.
- **What it would do on T1:** it gives 1.8 px before the correction and 1.7 px after two passes. It would loosen the
  tolerance from 1.5 px, the opposite of what helped.
- **The options:**
  - **(a) Recommended: leave the tolerance as it is.** The finish message and the log show the epipolar spread
    before and after, and suggest 1.0 px with T1 as the evidence. You set the tolerance in the tracking settings as
    usual.
  - (b) Set it by a rule fitted on T1: 1.35 × the robust SD of the corrected epipolar offsets, which is 1.0 px on T1.
    That is one rig's evidence.
  - (c) Today's rule, as for pinholes. It would put T1's tolerance at ~1.7 px.

**D2. Passes.**
- **(a) Recommended: one pass per click.** You rerun tracking between passes, and VSC composes the fields and guards
  against fitting twice on the same tracks.
- (b) A "passes" setting with which VSC reruns tracking itself between passes. That is automatic, but long (T1: ~1.5 h
  per pass), and it takes more GUI code: the VSC worker would drive OpenLPT.exe.
