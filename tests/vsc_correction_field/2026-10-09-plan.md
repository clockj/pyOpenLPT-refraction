## Changes

1. **Install.** `python build_local.py` with refract's interpreter rebuilds the GUI's module
   (`build-py/Release`) and exe (`build/Release/OpenLPT.exe`) from the source tree, which holds the tested change.
2. **The tracking settings page** (`gui/views/tracking_settings_view.py`) for tube and sphere projects (a PINCYL or
   PINSPH camera in the project). Plate and pinhole projects keep today's code paths.
   - **Save** keeps the object's settings that the form does not show, at every level: the tracer's line detector,
     OTF table and depth cue, and any other key. This applies when the form's object type equals the loaded one; the
     form's values win.
     - **Why:** today's Save rebuilds the object from the form, so a tube project loses its line detector. Validate
       saves first, so it loses it too.
   - **The view-volume estimate** projects tube and sphere cameras through the library (`projectBatchStatus`), as it
     already does for PINPLATE cameras, instead of as plain pinholes that ignore the refraction.
   - **Validate:** no change.
     - **Measured** (`s0_noise.py`): its line detector estimates the noise from the frame. The Python binding
       `findObject2D` has no camera argument, so it cannot take the configured per-camera noise as the run does.
     - **Effect on T1:** 2–4 % fewer detections than the run; 92 % of the run's are found.
     - **Why no fix now:** that needs a library binding argument, so it is left as an option.
   - **The field VSC's message:** the tolerance can be set on the settings page.
3. **The VSC finish and error handlers** (`gui/views/tracking_view.py`) quit and wait for the worker's thread
   before letting go of it.
4. **The vendored oracle:** re-copy `code/project_cylinder.py` (notes repo) to `test/refs/project_cylinder.py`. The
   only difference is an optional `box_trace` argument added for the paper's figure.

## Follow-up 2 (9 Oct, afternoon): the GUI detects as the tracking run does

You asked: "please fix the bugs on line detector, i want the gui behaves the same as the actual tracking code run
without gui. one final double check for me: is the refract+plate calibration in gui updated the same as our new
algorithm for that?"

**The reference** is the tracking run itself. Its IPR calls `ObjectFinder2D.findObject2D(frame, settings, camera
index)` on the frame as ImageIO loads it from the config's folder, and its log prints each frame's detections per
camera.

**Changes:**
- **The Python binding `findObject2D`** takes the camera's index (`cam_id`, default -1: as before). This is a library
  change; the GUI's module and the test build are rebuilt.
- **Validate** (tracking settings page) passes the index, falling back without it on an old module.
- **The plate/pinhole VSC's crops** (`vsc_service`) pass the index. With the peak finder nothing changes, since it
  takes no camera settings.
- **The field VSC detects with the run's own call:** ImageIO, the settings read from config.json, and the index. It
  no longer goes through OpenCV's frame and the line settings rebuilt in Python. Without the new binding it refuses
  to run, with the rebuild to do.

**Tests:**
- **D1:** on four runs' logs (T1, 20261008, the synthetic 3-camera set, the 20260727 plate run on X:), the run's call
  reproduces the log's counts.
  - **The field VSC** equals the run's call bit for bit; its path before the fix is compared too.
  - **The crops** use the configured noise.
  - **The plate run's crops** are unchanged with the index.
  - **Validate on the page** gives the log's counts.
- **S3** rerun against the run's counts.
- **G3** rerun on the installed module.
- **pytest** with the rebuilt module.

**The double check of the GUI's flat-window calibration** is a read-only comparison of what the GUI's
Pinhole+Refraction runs with what the real case (`cases/plate_20260727_T0`) ran.
