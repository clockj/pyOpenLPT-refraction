## 3. How to use it this afternoon

1. **Point Detection.**
   - **Load:** one folder per camera, with the frames in the same order.
   - **Detection settings:**
     - **Wand Type:** "Dark on Bright" for a backlit wand, "Bright on Dark" for lit balls.
     - **Radius Range:** set it to bracket both balls' radii in px. It also sets the speed: the background window is
       2.5 × the largest radius.
     - **Mode:** "ellipse".
   - **The rod settings:**
     - **Rod opening:** a little wider than the rod's image, narrower than the small ball's.
     - **Rod mask:** about half the rod's image width plus twice its blur. T13 used 25 and 18 px for a 0.3 mm rod at
       about 50 px/mm.
   - **Check before processing:** "Test Detect" on a few frames.
     - Each ball should get an ellipse that hugs its outline.
     - A red ellipse marked "overlap: dropped" means the balls touch in that view; that pair is skipped.
   - **Then "Process All Frames".** A frame is kept when every camera sees both balls apart.
2. **Calibration.**
   - **Settings:**
     - **Camera Model:** "Pinhole+Cylinder".
     - **Wand Length:** your wand's measured length.
     - **Distortion:** None or k1.
     - **Tube panel:** OD 201.6125 mm, wall 3.175 mm, water 1.333 (the defaults).
   - **"Precalibrate to Check"** (about 20 s) gives a first f and RMS per camera and fills the error table.
   - **"Run Calibration"** asks for a folder. Choose the project folder if you want `camFile/` there.
   - **When it ends:**
     - the Report tab shows the page;
     - the error table lists every frame, and clicking a row shows the detections and the fitted crosses;
     - the 3D View shows the tube.
3. **If frames look bad:**
   - tick them in the table (or use the error thresholds);
   - tick "Refit from the last result" (seconds);
   - run again.
4. **The page's checks name what the tests associate with a wrong or weak answer,** each with what to do:
   - balls not detected with "ellipse";
   - RMS above 1 px;
   - a camera with many rejected detections;
   - few frames;
   - wand ends beyond the fold radius (75.6 mm from your tube's axis);
   - a fitted wand length far from the nominal one.

**Do not run VSC on PINCYL cameras yet (O1 is paused).** VSC treats them as pinholes and would save PINHOLE files,
then point `config.json` at them.

## 6. Findings

1. **QtWebEngine in a conda env that is not activated (your shortcut).**
   - **The failure:** the helper process (`Library/lib/qt6/QtWebEngineProcess.exe`) died with 0xC0000135 (a DLL not
     found).
   - **The fix needs two things:**
     - the env's `Library/bin` first on PATH, as `conda activate` puts it (appended at the end, DLLs of the same
       name elsewhere on PATH are loaded instead and the renderer dies);
     - the Chromium sandbox off.
   - **Where:** `gui/app.py` sets both before the application starts.
   - **Effect on the rest:** none. The tracking executable needs no non-system DLLs, and the GUI's other children are
     Python of this env.
2. **A small C++/Python difference for a head-on camera (open; it predates this work).**
   - **What:** in G3's run, the C++ camera of cam0 (the one facing the tube head-on, 1.35e-6 rad from a half-turn)
     projects every point 2.75e-3 px off in u.
   - **The camFile holds the fitted camera exactly:** matrix, translation, f and cx agree to 1e-15 (D1d).
   - **The Python model is self-consistent:** its rays pass the points within 1e-14 mm (D1b).
   - **Not general:** the campaign's T10 and this work's G1 (also with head-on cameras) agree within 4e-4 px.
   - **Size:** ten times below the detector's noise. Worth a look in the C++ PINCYL projection.
3. **The camFiles' "Rotation Vector" line is 3.6e-5 rad off near a half-turn.** The C++ writer computes it; the matrix
   is exact. The GUI's camFile reader uses the matrix (D1d).
4. **VSC and the new flat-window camFiles.**
   - Their window ids group the cameras correctly.
   - Each camera's C++ plane point is its own point on the shared plane, so VSC's log will say "window plane mismatch
     across cameras" (`dpt` large, `dn` 0). It is the same plane.
5. **Pre-existing:** the full main window built offscreen exits with code 127 at shutdown, with HEAD's code too.
