### Phase G — the GUI: a pixel size per camera

**G1, the change you asked for.**
- **The table:** the wand tab's camera table gets a column **"Pixel (µm)"**, empty by default.
- **Detection:** the Radius Range and the ellipse mode's opening and rod mask stay as you set them, in camera 1's
  pixels (D1). A camera with a different pixel size gets them scaled by p₁ / p_c, both in Process Frames and in
  Test Detect. For this run: cam3 × 20 / 13.5 = 1.48.
- **f in mm:** the results page prints each camera's f in mm with its own pixel size. The Tube Settings' single
  "Pixel size" box, which only did that, goes.
- **No pixel sizes set:** the detection runs exactly as today.

The code changes:
- `view.py`: the column; the scales passed to the detection workers; the cylinder and plate jobs' pixel sizes.
- `wand_calibrator.py`: each detection task carries its camera's scale (default 1).
- `cylinder_wand_gui.Job` and `plate_wand_gui.Job`: `pixel_mm` may be a list per camera. The writers already take one.

**G2, optional (D2): images that start at different numbers.** The GUI pairs the i-th image of each camera's list.
For this run, loading every file of each camera would pair cam3's frame 0 with cams 1–2's frame 0, which is 2,396
frames off. With G2, a folder holding a Phantom `.chd` has its FirstImageNo read, and the cameras' lists are cut
to the images every camera saved; the log says how many were dropped. Without G2, you load cams 1–2 from
`frame002396` yourself.

**Tests** (G1, G2):
- **Light checks of the GUI:** it renders, looks right, and logs no errors.
- **One functional test:** the GUI's detection worker on the survey's frames with pixel sizes 20 / 20 / 13.5 gives
  the same balls as the case's per-camera detection, to 1e-6 px.
- **Regression:** with no pixel sizes set, the worker's output is identical to today's.

Only Python changes, so no rebuild is needed.

## 6. Changes while building (8 Oct)

- **T1's frames (your choice):** the first 250 raw frames, every frame (4,000 frames/s), instead of every 4th frame of
  all 1,001. Only these are copied and preprocessed; the p90 background comes from them.
- **The ghost control** shifts two cameras (cam2 by 50 frames, cam3 by 100), so that no camera pair holds a true
  match: with one camera shifted, the other two would still match true particles in the reduced loops (D3). It
  runs on frames 0-149, the frames the shifts leave.
- **The T0 detection** took longer than planned (about 2 h instead of 80 min): another session's runs share the CPU
  and the network share.
- **S3's settings, from S2 and the first frames:**
  - **2-D tolerance 2.0 px** (the plan: 1.5, or 1.0): of S2's true three-camera matches, 77 % lie within 1.5 px of the
    cam1-cam2 curve and 89 % within 2.0 px. The calibration's cameras agree to only 1-2 px (C1-H).
  - **Depth cue 0.8 px / 20 %:** S2's most selective setting (0.3 px / 25 %) keeps only 26 % of the true matches;
    0.8 px / 20 % keeps 80 % and 11 % of the random ones, with the third camera rejecting most random ones anyway.
  - **Three cameras for every match (D3 changed):**
    - **Why:** cam3 has about 5,200 detections per frame (cams 1-2: 450 and 950), so a two-camera match with cam3
      has several candidates on every curve, and the reduced loops doubled the time per frame.
    - **Measured:** the first frames of the D3 run took 80 s or more each.
    - **Instead:** the comparison with two cameras is the pair12 run below.
  - **Two IPR loops instead of three:** the line detector runs once per loop on every image, and the third loop
    matched at 4.5 px.
  - **cam3 cropped to rows 360-1575 (S1b),** the rows that see what cams 1-2 see. The detector's time grows with the
    image's area (27 s for cam3's full frame against 9 s for a 1280 x 800 one); the cropped camera maps every point
    to the same pixel shifted by 360 rows (2e-13 px).
  - **The result:** about 30 s per frame instead of 80.
- **Three cameras against two (T-compare):** cams 1-2 alone (pair12) with its own control (cam2 100 frames later), on
  frames 0-149, the frames the three-camera control covers.
