## 1. What changes

**Today the comparison of Fig. 14 and Supplement S8 runs in Python** (`code/paper_baselines.py`, run of 24 Sep):
- our search is the Python reference: 85.7 ms per point on the uniform set;
- the four iterative methods are pure Python too;
- the timings therefore compare Python implementations, and OpenLPT's C++ appears only in a separate agreement check.

**The new run puts every method in one C++ binary:**
- **Our search** is pyOpenLPT's C++ core, `src/srcMath/RefractCurved.cpp`, compiled read-only.
- **The four iterative methods** are line-for-line C++ ports of `code/paper_baselines.py`. Same algorithms, constants
  and stopping tests:
  - AFRT (Belden);
  - dewarping by Gauss–Newton and by Levenberg–Marquardt (Paolillo and Astarita);
  - LM shooting.
- **Timing:** every method is timed inside C++, on the same points, in the same pass.

**What stays in Python, unchanged:** the ground truth (traced census, endpoint brackets, Newton polish) and the scoring
(vector-Snell re-trace of every returned ray). They must share no code with what they judge. They are imported from
`code/paper_baselines.py`, which itself stays as it is.

## 5. Tests

Each test is a script in this folder that saves its output beside it.

- **C1. Build and smoke test:** the module builds and imports, and each method runs on one point.
- **C2. Our search in the module equals OpenLPT's.** Against the frozen `pyopenlpt.refract_curved.project_cylinder`
  and `project_sphere`, on 2000 points (uniform and far-branch-rich): the same lists, with the same rays to the last
  bit (same source, same compiler). Any difference is explained.
- **C3. The ports equal the Python methods.** On 200 points of every set and window, each method from its paper's
  start:
  - the same exit status and iteration count;
  - directions within 10⁻¹² rad where both converge;
  - at least 99 % of runs agree, and every difference is listed and explained. A last-bit difference in a library
    function can change a run that sits on a decision threshold.
- **C4. The C++ re-trace equals the Python re-trace:** the landing misses of 10⁴ rays agree to 10⁻¹⁵ relative.
- **C5. The comparison:** single start and multi-start, K = 1, 2, 4, …, 256, on every set.
  - Timing is interleaved per point (ours, AFRT, GN, LM, shooting), so a change in machine load hits every method alike.
  - Single start: three timing passes, median per point. Ray-path evaluations are recorded too, since they do not
    depend on load.
- **C6. Near grazing on the C++ core:** the 1950 draws of T2 (`code/tests/openlpt_audit/u6_t2_metres.py`, same seed),
  projected by the C++ core. The Python reference finds 1937 of them; the paper currently quotes that count.

**Report:** `2026-10-0X-report.md`, with every number the paper will quote and its key.

**Estimated cost:**
- code: about 800 lines of C++ and 400 of Python, most of it ported or reused;
- runs: about 45 min of ground truth in Python (0.1–0.4 s per point in the last run); the C++ runs take minutes.

## 6. The paper, after the results (with /writer)

- **9.2 opening:** introduce OpenLPT's C++ implementation first, since every test runs with it.
- **9.2.1, in your order:**
  1. **The criteria:**
     - *accuracy* is the landing miss of the traced line of sight;
     - *correctness* compares the returned list with the ground truth (every image, one of two, no answer, a false
       image). An empty list at an unseen point is correct.
  2. **The methods:** ours and the four iterative methods, all in C++; a single start as published, and the
     multi-start with re-tracing.
  3. **The comparison:** accuracy, correctness (Fig. 14), multi-start and time, and the losses near grazing.

  Then comes the bridge to 9.2.2. The separate near-branch test (1059 points) and the 160-ray round trip leave the
  main text; S8 keeps them.
- **Fig. 14 regenerated** from the C++ data by a new `code/make_paper_baselines_fig.py`, with its data in
  `paper/figures/data/`, copied with `--refresh` as for Fig. 15. Proposed panels:
  - (a) our search: the number of images (0, 1, 2) on the grid. It equals the traced ground truth at every point, so
    it is the answer key for the next four panels;
  - (b)–(e) the outcomes of the four iterative methods;
  - (f) the outcomes on each point set;
  - (g) every-image recovery against the median time per point, all in C++;
  - (h) accuracy: the landing miss of every returned ray, per method, with the 10⁻⁹ m tolerance marked.

  C6 replaces the near-grazing count if it differs.
